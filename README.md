> เอกสารข้อเสนอโครงการฉบับสมบูรณ์

## 2. บริบทและขอบเขตปัญหา

หน่วยงานหรือองค์กรขนาดเล็กมักมีทรัพย์สินและวัสดุที่ใช้ในภารกิจประจำ เช่น คอมพิวเตอร์ โต๊ะ เก้าอChair เครื่องเขียน อุปกรณ์สำนักงาน และครุภัณฑ์อื่น ๆ ที่มีจำนวนค่อนข้างมากและมีการเคลื่อนไหวบ่อย เช่น รับเข้า เบิกจ่าย ปรับปรุง ย้ายสถานที่ หรือทำลายทิ้งจากการใช้งานจริง

ปัญหาที่พบคือข้อมูลส่วนใหญ่ถูกบันทึกอยู่ในแผ่นงาน หรือเอกสารกระดาษ และมีโอกาสเกิดข้อผิดพลาดจากการคีย์ข้อมูลซ้ำ การลืมบันทึกการเคลื่อนไหว และความยากลำบากในการค้นหาข้อมูลย้อนหลัง หากมีการใช้ระบบอัตโนมัติที่เก็บข้อมูลเป็นไฟล์ไบนารีและมีการควบคุมรูปแบบระเบียนแบบ fixed-length จะช่วยให้ระบบมีความเสถียรและสามารถตรวจสอบข้อมูลได้แม่นยำขึ้น

โครงการนี้จึงออกแบบและพัฒนาระบบจัดการคลังพัสดุและครุภัณฑ์ขึ้น เพื่อให้สามารถทำงานได้ในเทอร์มินัลโดยไม่ต้องพึ่งฐานข้อมูลภายนอก และใช้ไฟล์ไบนารีเป็นแหล่งจัดเก็บข้อมูลหลัก การบันทึกข้อมูลจึงมีความต่อเนื่อง ชัดเจน และสามารถตรวจสอบได้ง่าย

### ผู้ใช้งานเป้าหมาย

- เจ้าหน้าที่คลังพัสดุ
- ผู้ดูแลครุภัณฑ์
- ผู้ตรวจสอบรายการรับเข้าและเบิกจ่าย
- ผู้บริหารหรือหัวหน้างานที่ต้องการสรุปสถานะคลัง

### ขอบเขตการทำงาน

1. จัดการข้อมูลพัสดุและครุภัณฑ์
2. จัดการข้อมูลหมวดหมู่
3. บันทึกประวัติการรับเข้า เบิกจ่าย และปรับยอดคงเหลือ
4. ค้นหาและกรองข้อมูล
5. แสดงสถิติคลังแบบสรุป
6. สร้างรายงาน `report.txt`
7. รองรับระเบียนแบบ fixed-length และการลบแบบ logical delete

### ปริมาณข้อมูลเป้าหมาย

- พัสดุหลักอย่างน้อย 50 ระเบียน
- หมวดหมู่อย่างน้อย 8 ระเบียน
- ประวัติการเคลื่อนย้ายอย่างน้อย 100 ระเบียน
- รองรับการขยายข้อมูลโดยไม่เปลี่ยนขนาดระเบียนเดิม

### สิ่งที่อยู่นอกขอบเขต

- ระบบผู้ใช้หลายระดับและระบบล็อกอินผ่านเครือข่าย
- ฐานข้อมูล SQL หรือฐานข้อมูลภายนอก
- เว็บแอปพลิเคชันและส่วนติดต่อแบบกราฟิก
- การเชื่อมต่อเครื่องอ่านบาร์โค้ด

## 3. ข้อกำหนดเชิงหน้าที่

โปรแกรมทำงานผ่านเมนูหลักดังนี้

```text
===== ระบบคลังพัสดุและครุภัณฑ์ =====
1) Add Item          เพิ่มพัสดุ
2) Update Item       แก้ไขข้อมูลพัสดุ
3) Delete Item       ลบพัสดุแบบ Logical Delete
4) View              ดูข้อมูล
5) Stock Movement    รับเข้า/เบิกจ่าย
6) Generate Report   สร้างรายงาน
0) Exit              ออกจากโปรแกรม
เลือกเมนู:
```

### 3.1 Add Item

- รับรหัสพัสดุ ชื่อพัสดุ หมวดหมู่ หน่วยนับ จำนวนคงเหลือ จุดต่ำสุด และราคาต่อหน่วย
- ตรวจสอบรหัสต้องเป็นจำนวนเต็มบวกและไม่ซ้ำ
- ตรวจสอบข้อความไม่ว่างและไม่เกินความยาวที่กำหนด
- ตรวจสอบจำนวนและราคาต้องไม่ติดลบ
- เพิ่มระเบียนลงช่องว่างในไฟล์ก่อน หากไม่มีช่องว่างจึงต่อท้ายไฟล์
- บันทึกประวัติการเพิ่มข้อมูลลงไฟล์ `movements.dat`

### 3.2 Update Item

- ค้นหาด้วย `item_id`
- อนุญาตให้แก้ไขชื่อ หมวดหมู่ หน่วยนับ จุดต่ำสุด และราคาต่อหน่วย
- ไม่อนุญาตให้แก้ไขรหัสพัสดุ
- ตรวจสอบว่าระเบียนมีสถานะ Active
- บันทึกประวัติการแก้ไขก่อนและหลังการเปลี่ยนแปลงที่จำเป็น

### 3.3 Delete Item

- ค้นหาด้วย `item_id`
- ไม่ลบไบต์ออกจากไฟล์จริง แต่เปลี่ยน `status` เป็น Deleted
- ต้องยืนยันก่อนลบ
- พัสดุที่มีจำนวนคงเหลือมากกว่า 0 ไม่ควรถูกลบจนกว่าจะเคลียร์ยอดหรือผู้ใช้ยืนยันให้ลบต่อ
- ช่องที่ถูกลบจะถูกบันทึกใน free-list เพื่อใช้ซ้ำใน Add ครั้งถัดไป

### 3.4 View

มีเมนูย่อยดังนี้

1. ดูพัสดุรายการเดียวด้วยรหัส
2. ดูพัสดุทั้งหมด
3. กรองตามหมวดหมู่หรือสถานะ
4. ค้นหาจากคำในชื่อพัสดุ
5. ดูรายการที่มีจำนวนต่ำกว่าจุดต่ำสุด
6. แสดงสถิติ เช่น จำนวนระเบียน Active/Deleted มูลค่ารวม และจำนวนพัสดุใกล้หมด

### 3.5 Stock Movement

- `RECEIVE`: รับพัสดุเข้า เพิ่มจำนวนคงเหลือ
- `ISSUE`: เบิกพัสดุออก ลดจำนวนคงเหลือ
- ไม่อนุญาตให้เบิกเกินจำนวนคงเหลือ
- ทุกการเคลื่อนไหวต้องอ้างอิง `item_id` และจำนวนที่ถูกต้อง
- ประวัติไม่ถูกลบ เพื่อใช้ตรวจสอบย้อนหลัง

### 3.6 Generate Report

สร้างไฟล์ `report.txt` โดยประกอบด้วย

- ส่วนหัวชื่อระบบ วันเวลาที่สร้าง และเวอร์ชัน
- รูปแบบไฟล์และ endianness
- ตารางพัสดุ Active
- จำนวนระเบียน Active, Deleted และช่องว่าง
- มูลค่าพัสดุคงเหลือรวม
- รายการที่ต่ำกว่าจุดสั่งซื้อ
- สถิติตามหมวดหมู่
- ประวัติการทำงานล่าสุด

### 3.7 Exit

ก่อนออกจากโปรแกรมต้อง flush ข้อมูล ปิดไฟล์อย่างปลอดภัย และสร้างรายงานอัตโนมัติหากยังไม่มีไฟล์รายงาน

## 4. สเปกไฟล์และระเบียน

ระบบใช้ไฟล์ไบนารี 3 ไฟล์ และไฟล์รายงานข้อความ 1 ไฟล์

| ไฟล์ | ประเภท | หน้าที่ |
|---|---|---|
| `items.dat` | Binary | ข้อมูลพัสดุหลัก ระเบียน fixed-length |
| `categories.dat` | Binary | ข้อมูลหมวดหมู่ ระเบียน fixed-length |
| `movements.dat` | Binary | ประวัติรับเข้า/เบิกจ่าย ระเบียน fixed-length |
| `report.txt` | Text UTF-8 | รายงานสรุปที่สร้างจากข้อมูลล่าสุด |

### 4.1 ข้อตกลงร่วมของไฟล์ไบนารี

- ใช้ Little-Endian อย่างชัดเจน
- ใช้ `struct.Struct` เพื่อกำหนดรูปแบบระเบียน
- ใช้ `read()` ตามขนาด `record_size` เท่านั้น
- สตริงใช้ UTF-8 และเติมไบต์ว่าง `\x00` ให้ครบขนาด
- ก่อน `unpack` ต้องตรวจสอบว่าอ่านได้ครบขนาดระเบียน
- ไฟล์ทุกไฟล์มี file header เพื่อระบุ magic, version, record size และจำนวนระเบียน
- ระเบียนที่ลบใช้ logical delete ไม่ทำให้ขนาดระเบียนอื่นเปลี่ยน

### 4.2 File Header

ส่วนหัวมีขนาดคงที่ 32 ไบต์

| ฟิลด์ | รูปแบบ | ขนาด | คำอธิบาย |
|---|---:|---:|---|
| magic | `4s` | 4 | รหัสไฟล์ เช่น `ITEM` |
| version | `H` | 2 | เวอร์ชันรูปแบบไฟล์ |
| record_size | `H` | 2 | ขนาดระเบียน |
| record_count | `I` | 4 | จำนวนระเบียนที่เคยจัดสรร |
| active_count | `I` | 4 | จำนวนระเบียน Active |
| deleted_count | `I` | 4 | จำนวนระเบียน Deleted |
| free_head | `I` | 4 | ตำแหน่งช่องว่างแรก หรือ `0xFFFFFFFF` |
| created_ts | `Q` | 8 | Unix timestamp |

รูปแบบตัวอย่าง: `'<4sHHIIIIQ'` มีขนาด 32 ไบต์ และใช้ `struct.Struct` ในการอ่าน/เขียน

### 4.3 ระเบียน `items.dat`

รูปแบบตัวอย่าง: `'<I I 32s 16s 12s I I f B 3x'` รวม 84 ไบต์

| ฟิลด์ | ชนิด | ขนาด | คำอธิบาย |
|---|---:|---:|---|
| `item_id` | `I` | 4 | รหัสพัสดุ ไม่ซ้ำ |
| `category_id` | `I` | 4 | รหัสหมวดหมู่ |
| `name` | `32s` | 32 | ชื่อพัสดุ UTF-8 สูงสุด 32 ไบต์ |
| `unit` | `16s` | 16 | หน่วยนับ เช่น ชิ้น กล่อง |
| `location` | `12s` | 12 | ตำแหน่งจัดเก็บ |
| `quantity` | `I` | 4 | จำนวนคงเหลือ |
| `reorder_level` | `I` | 4 | จุดสั่งซื้อขั้นต่ำ |
| `unit_price` | `f` | 4 | ราคาต่อหน่วย |
| `status` | `B` | 1 | 1 = Active, 0 = Deleted |
| padding | `3x` | 3 | สำรองเพื่อจัด alignment |

### 4.4 ระเบียน `categories.dat`

รูปแบบตัวอย่าง: `'<I 24s 80s B 3x'` รวม 116 ไบต์

| ฟิลด์ | ชนิด | ขนาด | คำอธิบาย |
|---|---:|---:|---|
| `category_id` | `I` | 4 | รหัสหมวดหมู่ |
| `name` | `24s` | 24 | ชื่อหมวดหมู่ |
| `description` | `80s` | 80 | รายละเอียดหมวดหมู่ |
| `status` | `B` | 1 | 1 = Active, 0 = Deleted |
| padding | `3x` | 3 | ไบต์สำรอง |

### 4.5 ระเบียน `movements.dat`

รูปแบบตัวอย่าง: `'<Q I B I I f 32s 16s B 3x'` รวม 80 ไบต์

| ฟิลด์ | ชนิด | ขนาด | คำอธิบาย |
|---|---:|---:|---|
| `timestamp` | `Q` | 8 | Unix timestamp |
| `log_seq` | `I` | 4 | ลำดับประวัติ |
| `op_code` | `B` | 1 | 1 = ADD, 2 = UPDATE, 3 = DELETE, 4 = RECEIVE, 5 = ISSUE |
| `item_id` | `I` | 4 | รหัสพัสดุ |
| `quantity` | `I` | 4 | จำนวนที่เปลี่ยนแปลง |
| `balance` | `f` | 4 | มูลค่าหรือยอดที่เกี่ยวข้องหลังรายการ |
| `operator` | `32s` | 32 | ผู้ปฏิบัติงาน |
| `note` | `16s` | 16 | หมายเหตุสั้น ๆ |
| `status_after` | `B` | 1 | สถานะหลังทำรายการ |
| padding | `3x` | 3 | ไบต์สำรอง |

> ขนาดจริงของแต่ละ `Struct` จะถูกตรวจสอบด้วย `.size` ในโปรแกรม และเอกสารต้องปรับให้ตรงตามค่าจริงเสมอ

### การเข้ารหัสข้อความ

ฟังก์ชันเขียนสตริงต้องเข้ารหัสด้วย UTF-8 แล้วตัดให้ไม่เกินขนาดไบต์ที่กำหนดก่อนบันทึกลง binary file หากข้อความยาวเกินจะตัดข้อความตามขนาดที่กำหนดให้ปลอดภัย

## 5. ผังการทำงาน (Processing Flows)

### 5.1 การเริ่มต้นระบบ

1. เปิดหรือสร้างไฟล์ไบนารีทั้ง 3 ไฟล์
2. ตรวจสอบ magic, version และ `record_size`
3. หากไฟล์ว่าง ให้เขียน header ใหม่
4. หาก header หรือระเบียนเสีย ให้แจ้งเตือนและหยุดการแก้ไขข้อมูล
5. โหลดค่า header และ free-list
6. แสดงเมนูหลัก

### 5.2 Add

```text
รับข้อมูล -> ตรวจสอบรูปแบบ -> ตรวจรหัสซ้ำ
        -> หาช่องว่างจาก free-list
        -> pack ระเบียน -> เขียนลงตำแหน่ง
        -> ปรับ header -> เขียน movement log
        -> แจ้งผลสำเร็จ
```

### 5.3 Update

```text
รับ item_id -> ค้นหา offset -> ตรวจ Active
          -> รับค่าใหม่ -> ตรวจสอบข้อมูล
          -> pack ระเบียนใหม่ที่ขนาดเดิม
          -> เขียนทับตำแหน่งเดิม
          -> บันทึก UPDATE log
```

### 5.4 Delete

```text
รับ item_id -> ค้นหา -> ตรวจว่ามีและ Active
          -> ขอการยืนยัน
          -> เปลี่ยน status เป็น Deleted
          -> เพิ่มตำแหน่งลง free-list
          -> ปรับ header -> บันทึก DELETE log
```

### 5.5 View

```text
เลือกชนิดการดู -> อ่านทีละ record_size
                -> ตรวจระเบียนครบถ้วน
                -> unpack
                -> ข้าม Deleted ตามตัวกรอง
                -> แสดงผลหรือคำนวณสถิติ
```

### 5.6 Stock Movement

```text
รับ item_id และประเภท RECEIVE/ISSUE
-> ตรวจ item และจำนวน
-> ตรวจไม่ให้ยอดติดลบ
-> ปรับ quantity ของ items.dat
-> append movement record
-> ปรับ header และแสดงยอดใหม่
```

## 6. แผนการรายงาน

### รายละเอียดส่วนประกอบของรายงาน

1. **ส่วนหัวรายงาน**
   - ชื่อระบบ
   - วันและเวลาที่สร้างรายงาน
   - เวอร์ชันของโปรแกรม
   - รูปแบบ Endianness
   - รูปแบบการเข้ารหัสข้อความ

2. **ตารางรายการพัสดุ**
   - แสดง `item_id`
   - รหัสหมวดหมู่
   - ชื่อพัสดุ
   - หน่วยนับ
   - จำนวนคงเหลือ
   - ราคาต่อหน่วย
   - สถานะ `Active` หรือ `Deleted`

3. **ส่วนสรุปข้อมูล**
   - จำนวนระเบียนทั้งหมด
   - จำนวนระเบียน Active
   - จำนวนระเบียน Deleted
   - จำนวนพัสดุคงเหลือรวม
   - จำนวนช่องว่างในไฟล์
   - จำนวนรายการที่ต่ำกว่าจุดสั่งซื้อ
   - มูลค่าพัสดุคงเหลือรวม

4. **สถิติราคา**
   - ราคาต่อหน่วยต่ำสุด
   - ราคาต่อหน่วยสูงสุด
   - ราคาต่อหน่วยเฉลี่ย
   - คำนวณเฉพาะพัสดุที่มีสถานะ `Active`

5. **สถิติตามหมวดหมู่**
   - แสดงจำนวนพัสดุในแต่ละหมวดหมู่
   - ไม่นับรายการที่มีสถานะ `Deleted`

6. **รายการพัสดุใกล้หมด**
   - แสดงรายการที่มีจำนวนคงเหลือน้อยกว่าหรือเท่ากับ `reorder_level`
   - แสดงรหัสพัสดุ ชื่อ จำนวนคงเหลือ และจุดสั่งซื้อ

7. **ประวัติการทำงานล่าสุด**
   - แสดงรายการเคลื่อนไหวล่าสุดตามลำดับเวลา
   - รองรับรายการ `ADD`, `UPDATE`, `DELETE`, `RECEIVE` และ `ISSUE`
   - แสดงเวลา รหัสพัสดุ จำนวนที่เปลี่ยนแปลง และยอดคงเหลือหลังรายการ

รายงานต้องไม่แก้ไขไฟล์ข้อมูลต้นฉบับ ได้แก่ `items.dat`, `categories.dat` และ `movements.dat` หากตรวจพบไฟล์เสียหาย ให้แสดงสถานะ `CORRUPTED` พร้อมรายละเอียดของปัญหา และต้องไม่เขียนทับข้อมูลเดิม

## 9. ความเสี่ยงและการบรรเทา

| ความเสี่ยง | ผลกระทบ | แนวทางบรรเทา |
|---|---|---|
| คำนวณขนาด `struct` ผิด | อ่านระเบียนเหลื่อมทั้งไฟล์ | ใช้ `Struct.size` และทดสอบ round-trip pack/unpack |
| การจัดแนวข้อมูลไม่ตรงกัน | ไฟล์ใช้ข้ามเครื่องไม่ได้ | ระบุ Little-Endian และใช้ `struct.pack` อย่างชัดเจน |
| ตัด UTF-8 กลางอักขระ | ข้อความเสียหรือ decode ไม่ได้ | จำกัดด้วยจำนวนไบต์และตัดข้อความให้พอดีกับ fixed-length |
| ไฟล์เสียหรือเขียนไม่ครบ | ข้อมูลสูญหาย | ตรวจ magic, version, ขนาดไฟล์ และทำ backup ก่อนเขียน |
| โปรแกรมหยุดระหว่างเขียน | header กับระเบียนไม่สอดคล้อง | flush, ปิดไฟล์อย่างปลอดภัย และทำการบันทึกแบบ atomic |
| ลบข้อมูลถาวรโดยไม่ตั้งใจ | กู้คืนยาก | ใช้ logical delete และขอการยืนยันก่อนลบ |
| เบิกเกินยอด | จำนวนคงเหลือผิด | ตรวจยอดก่อนเขียนและทำรายการแบบ atomic |
| ข้อมูลซ้ำ | รายงานคลาดเคลื่อน | ตรวจ unique key ก่อน Add และตรวจซ้ำในขั้นตอนเปิดไฟล์ |

## 12. สรุป

โครงการนี้มุ่งพัฒนาระบบคลังพัสดุและครุภัณฑ์ที่แสดงให้เห็นความเข้าใจเรื่องการจัดการไฟล์ไบนารีแบบ fixed-length, การใช้ `struct` ของ Python, การบันทึกข้อมูลแบบมีโครงสร้าง, การตรวจสอบความสมบูรณ์ของข้อมูล, และการสร้างรายงานแบบสรุปในรูปแบบข้อความ เพื่อให้ผู้ใช้สามารถใช้งานระบบในเทอร์มินัลได้อย่างมีประสิทธิภาพและยืดหยุ่น โดยคงรูปแบบงานที่สอดคล้องกับข้อกำหนดของรายวิชาหรือโครงการพัฒนาภาษา Python ด้าน File I/O และ Data Management

### สรุปแบบสั้นสำหรับเชิงประเด็น

- ระบบจัดการคลังพัสดุและครุภัณฑ์แบบเทอร์มินัล
- เก็บข้อมูลในไฟล์ไบนารี 3 ไฟล์ด้วย `struct`
- รองรับการ Add, Update, Delete, View และ Stock Movement
- ทำงานบน Python 3.10+
- สร้างรายงาน `report.txt` เป็นไฟล์ข้อความ UTF-8
- ใช้ logical delete แทนการลบข้อมูลถาวร
- มีการตรวจสอบอินพุตและความสมบูรณ์ของไฟล์
